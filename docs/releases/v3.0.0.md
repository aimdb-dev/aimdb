# AimDB v3.0.0 Release Notes

**Every value knows when it was written. Connectors move data without allocating. ROS 2 speaks AimDB.**

> Typed dataplane for distributed systems

---

## 🎯 Highlights

AimDB 3.0 stamps **every record write** with the time it happened, from one monotonic clock per instance, and carries that stamp through every read, every transport and every tool. The wire protocol moves to **AimX 4.0** to carry it.

Underneath, connectors now drive both directions from their own task over a **zero-allocation boundary**: core runs no task per connector or per route, and a steady-state message crosses without allocating. Inbound links accept **wildcards** (`mqtt://sensors/{device}/temp`), and a new **Zenoh connector** makes AimDB records ROS 2 topics without a ROS install on the AimDB side.

This is a breaking release. AimX 4.0 peers **refuse 3.x at the handshake**, so servers, clients, the CLI, the MCP server and browser bridges must be upgraded together.

---

## 💥 Breaking Changes

### 1. Write timestamps — reads return `Stamped<T>` (#326, design 058)

Every write is stamped, and every read returns the stamp with the value:

```rust
// 2.x
let temp: Temperature = reader.recv().await?;

// 3.0
let sample = reader.recv().await?;   // Stamped<Temperature>
let written_at = sample.stamp();     // read the stamp first: `.value` moves out
let temp = sample.value;
```

This applies to `Reader::recv` / `try_recv`, `AimDb::latest`, the JSON reads, `RecordValue`, and `aimdb-sync`'s `get*` family. Buffers hold `Stamped<T>`. `JoinTrigger::Input` and `OutboundMessage` carry the input's `metadata`.

Time reads moved to a per-instance `InstanceClock`: `RuntimeOps` drops `now_nanos` / `unix_time` and gains `new_clock()`. `ctx.time().now()` and `AimDb::now()` return a monotonic `Stamp` measured from instance start, the clock that stamps writes. Wall-clock time stays separate, as `ctx.time().unix_time()`. On Tokio the monotonic clock follows paused time.

### 2. AimX 4.0

`ts` is mandatory on `event` and `snap` frames. `record.get` replies `{value, ts}`, `record.drain` values are `{value, ts}`, and `record.set` echoes `{status, value, ts}`. A value frame without `ts` is malformed, and 3.x peers are refused at `hello`.

- **Browser bridges** connect with `?v=4.0`. `WasmDb.get` and `subscribe` callbacks yield `{ value, ts }`, with `ts` as a `BigInt`.
- **`aimdb-client`**: `get_record` returns `Stamped<Value>`, `RecordUpdate` gains `ts`, and a value without `ts` is `ClientError::Protocol`.
- **`run_client`** (serial, TCP, UDS) takes a `RuntimeContext`. Outside an instance, build one with `RuntimeContext::new(Arc::new(adapter))`.

### 3. Connector SPI: a pull model (design 054)

`pump_sink`, `pump_source`, `Source`, the `Connector` trait, `TopicProvider`, `OutboundRoute`, `collect_outbound_routes` and the `Serialized*` types are removed. A connector builds `InboundDispatch` and `OutboundRoutes` in `build()` and drives both directions from its own transport task. `with_topic_provider` becomes `with_topic_writer` / `with_topic_fn`, which write into a bounded buffer.

Every connector gets its router from `AimDb::inbound_router(scheme, grammar)`. `RouterBuilder`, `Route`, `collect_inbound_routes` and the public `Router::new` are gone. Routes carry `record_index`, and `ConnectorConfig` is `#[non_exhaustive]`.

The user-facing `link_to` / `link_from` API is unchanged. Only custom connectors need porting.

### 4. Connector-specific changes

- **KNX**: `KnxConnector::new(binder, delay, url)` no longer takes `&'static Channels`. Delete the `static CHANNELS` and the argument.
- **Embassy adapter**: `EmbassySink` / `EmbassySource` (and their `Raw` variants) are removed.
- **WebSocket**: read grants are **record-key** patterns (`read_patterns`, `can_read`), resolved once at the upgrade into a per-client record bitset. `authorize_subscribe` / `authorize_query` / `authorize_list` are removed, and their logic moves into `authenticate`. `record.list` and `record.query` return only what the client may read. See the security fix below.
- **Topics**: `{` and `}` are pattern syntax on every connector. Outbound links reject `{…}` topics at `build()`. KNX, WebSocket, TCP, UDS and serial refuse `{…}` links.

### 5. Tools

- **`aimdb` CLI exit codes** are per failure class: 1 = refused, 2 = usage, 3 = environment / retryable, 4 = watch timeout. Scripts that treated 1 as "unreachable" must check for 3.
- **`aimdb-mcp`** offers write tools (`set_record`, `reset_*`) only with `--allow-writes`.

### 6. Smaller surface changes

- `GraphNode` gains `schema` and `outbound_links`. `InboundConnectorLink` and `RecordMetadata` are `#[non_exhaustive]`.
- `aimdb-sync`: `SyncProducer::try_set`, `try_set_value` and `SyncError::SetTimeout` are removed. Use `set` / `set_value`.
- `aimdb-knx-connector`'s `critical-section-std-impl` is a deprecated no-op.
- `aimdb-codegen`'s generated KNX wiring follows the new `KnxConnector::new`, and generated manifests now target the 3.0 crate set.

## ✨ Also New

- **Links as values (#388–#391)**: build a link before its record and attach it with `reg.input(..)` / `reg.output(..)`. `builder.connect(..)` returns a scheme-free handle (`OutboundLink::on(mqtt, "sensors/temp")`), and `Linkable` contracts get `publish` / `subscribe` with their own codec.
- **Wildcard inbound links (design 055)**: `link_from("mqtt://sensors/{device}/temp")`, captures through `with_match_deserializer`, and bounded `KeyId` tables via `.key("device", 1024)`. MQTT understands topic filters (`+`, `#`).
- **Zenoh connector and ROS 2 (design 053)**: `Ros2Connector` follows rmw_zenoh's conventions, so `ros2 topic echo` / `pub` see AimDB as a node. `#[derive(RosMessage)]` and the new `aimdb-cdr` crate (`no_std` OMG CDR) support it.
- **Build identity (design 057)**: the new `aimdb-build-info` crate embeds name, version, git revision, profile and target in a fixed-layout section. `aimdb instance info` and MCP `get_instance_info` show it.
- **Graph introspection** reports each record's schema and outbound link addresses.
- **Current values over HTTP**: `AimDb::latest::<T>(key)`, and WebSocket additional routes can extract `Extension<AimDb>`.
- **`aimdb watch --new` / `--timeout`** wait for the next update. `aimdb_client::watch` offers the same flow to other clients.
- **Logging**: core's `log_*!` lines reach `defmt` on Embassy devices. Library crates report operational failures through those macros, and the persistence crates and the Embassy adapter gain `log` features.
- **MQTT**: several brokers per database with a configurable link scheme, `with_qos` on inbound subscriptions, and an embedded backend that encodes into one write ring.
- **Deterministic startup**: record tasks start in registration order, with a seeded permutation available for tests.

## 🔒 Security & Correctness Fixes

- **WebSocket read grants no longer leak records they don't name.** Grants used to be matched against topics, so a client granted one record's topic received every record publishing there. Grants are now resolved against record keys and enforced at every delivery point.
- **A failing listener no longer stalls a session server.** `serve` yields after accept errors and stops on `Closed`.
- **AimX over serial**: every reconnect gets its events, and an ended subscription no longer cancels a newer one with the same id.
- **UDS** `recv` is cancel-safe.
- **Embedded MQTT** advertises its maximum packet size, so an oversized retained message no longer causes a reconnect loop.
- **`EmbassyUart`** no longer stalls mid-reply on embassy-stm32 0.6.0. It flushes after each write until an upstream release carries the fix (#385).
- A second MQTT connector for the same scheme fails the build instead of silently competing.

## 🚀 Migration Guide

**Step 1 — bump the crates together.** See the table below. Every crate that depends on `aimdb-core` moves to a new minor version.

**Step 2 — unwrap `Stamped<T>` at reads.** Add `.value` where you consumed a bare `T` from `recv`, `try_recv`, `latest` or `aimdb-sync`'s `get*`. Keep `.stamp()` where the write time is useful.

**Step 3 — move time reads to the context, keeping monotonic and wall-clock time apart.**

- *Monotonic* (`runtime.now_nanos()`, or 2.x `ctx.time().now()` returning `u64`) → `ctx.time().now()` or `db.now()`, which return a `Stamp` measured from instance start. Use `Stamp::since` for elapsed time and ages (`db.now().since(sample.stamp())`), and `as_nanos()` if you need the raw count.
- *Wall clock* (`runtime.unix_time()`) → `ctx.time().unix_time()`, or `db.runtime_ctx().time().unix_time()` outside a task. It still returns `Option<(secs, nanos)>` since the Unix epoch. **Do not** replace it with `now()`: a stamp is instance-relative, so storing it where Unix time was expected changes the meaning of persisted or externally correlated timestamps.

**Step 4 — KNX users:** drop `static CHANNELS` and the `Channels` argument to `KnxConnector::new`.

**Step 5 — custom connectors:** port to `InboundDispatch` / `OutboundRoutes` and `inbound_router`. Read `route.record_index`. The built-in connectors are working references.

**Step 6 — WebSocket auth:** rewrite topic read grants as record-key grants, and move any `authorize_subscribe` / `authorize_query` / `authorize_list` logic into `authenticate`.

**Step 7 — tooling:** add `--allow-writes` to MCP configurations that need write tools. Update scripts that branch on `aimdb` exit codes.

**Step 8 — upgrade clients and servers together.** A 3.x peer cannot talk to a 4.0 peer, in either direction. Hand-rolled browser clients must send `?v=4.0`.

## ⚠️ Known Limitations

- **`aimdb-embassy-adapter` with `embassy-sync`**: the adapter needs `poll_next_message` / `poll_changed`, which are merged upstream but not in embassy-sync 0.8.0. The workspace patches them in from git, and patches are not published, so the crate is published without a verification build. A downstream build of its `embassy-sync` feature needs the same `[patch.crates-io]` entries until an embassy-sync release carries those APIs (#386).
- **`embedded-tls`** (the MQTT connector's optional embedded `mqtts://` feature) pulls a `crypto-bigint` affected by RUSTSEC-2026-0387 until an upstream release moves off `elliptic-curve` 0.13 (#340).
